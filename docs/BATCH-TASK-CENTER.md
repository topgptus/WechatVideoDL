# 批量任务中心：功能与部署说明

## 使用方式

在导航中打开「批量任务」，粘贴多条微信视频号链接或分享文本；单批最多 30 条，自动去重。
除了多链接输入，批量创建界面复用单任务的五种任务模式、提示词预设、可编辑 Prompt、
Markdown/TXT 格式及 MP4、AI 分析、AI 旁白、SenseVoice 逐字稿与时间轴选项。

**本批次统一设置**：每一条视频使用同一组参数，但分别排队、处理、产生任务记录与文件。
已经开始的任务不能单独修改本批次选项。

处理过程中提供单批次进度、暂停/恢复待执行、取消尚未开始、失败重试。
正在执行的任务不被强制中断。后台持久化待执行任务，服务重启后可恢复待执行队列。
复用现有单 worker，不增加元宝会话并发。

完成后使用「下载本批次全部成果 ZIP」，按 `任务 ID/原文件名` 分目录保存：
MP4、AI 分析、AI 整理版旁白、原始/时间轴逐字稿、封面。
任务未完成时可下载**已生成**的成果，不会虚构或重复文件。
旧的 `/api/batches/<id>/texts.zip` API 保留供老客户端使用（只包含文本）。

## 服务端接口

- `POST /api/batches`：创建当前账号的一批任务，接收 `text` 或 `urls`，及单任务已有配置字段。
- `GET /api/batches`、`GET /api/batches/<id>`：列举和查询自己可访问的批次。
- `POST /api/batches/<id>/action`：`pause` / `resume` / `cancel` / `retry`。
- `GET /api/batches/<id>/all.zip`：导出所有已存在成果。
- `GET /api/batches/<id>/texts.zip`：向后兼容的纯文本合集。

所有接口继承登录、管理员与普通用户权限隔离；更改类接口沿用 CSRF 保护。
ZIP 限制为当前可见批次数据库所列的文件，不从用户输入接受磁盘路径，
不允许符号链接、目录穿越或非白名单扩展名。

## 运维与容量限制

升级时自动迁移原 SQLite `history.db`，新增批次和队列字段；不会删除旧记录。
升级前备份私有 `data/`，尤其是数据库和元宝凭据，**绝不可提交到 Git**。

全成果 ZIP 的输入文件总计默认最多 8 GiB，使用临时磁盘文件流式返回，
预检空余空间（额外预留至少 512 MiB）；大尺寸 MP4 与 JPG 直接储存，
文本使用 ZIP 压缩，避免把整包放入内存。
若达到大小限制或空间不足，可在历史记录页逐条下载文件。

原始逐字稿依赖可选的本地 SenseVoice 工作进程及离线模型，
须先验证工作进程的心跳和队列可用，才把 `LOCAL_TRANSCRIPTION_ENABLED` 改为 `true`。
没有 SenseVoice 时，仍可执行不包含逐字稿的批量任务；不会自动改用 Whisper。

管理员可在「设置 → 元宝连接」导入全站共享的 Cookie 和 Session，
见 [元宝统一登录配置](YUANBAO-ADMIN-CREDENTIALS.md)。
此配置与用户任务/文件的所有权隔离是不同概念。

## 测试建议

先对 2～3 条授权视频验证批量任务创建、各模式交互、轮询进度，
再确认 ZIP 中视频与对应文本的数量、文件可播放/可读；
用另一普通用户检查无法访问非本人批次或其 ZIP。
项目测试涵盖混合打包、跨用户/跨批次隔离、缺失文件、异常路径与限额。
