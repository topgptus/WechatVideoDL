# WechatVideoDL 多用户登录、管理员权限与安全边界

版本：2026-10-17。适用范围：WechatVideoDL Docker 部署；不依赖开发者的本地用户名。

## 首次登录与历史迁移

全新安装首次启动读取私有 .env 中的 WEBUI_USERNAME 和 WEBUI_PASSWORD，在 /data/auth.db 尚无用户时创建首位管理员，并立即将此用户设为**唯一受保护的超级管理员**；原有无归属历史任务关联初始管理员，不重新下载或清空内容。

对于已有多用户但没有 is_superadmin=1 的旧数据库：首次升级使用 SUPERADMIN_BOOTSTRAP_USERNAME 指定**现有已启用的管理员**（不填则使用 WEBUI_USERNAME）。目标用户名不存在、未启用或不是管理员时，启动将拒绝完成账号初始化，不会静默将其他人提升为超级管理员。升级前建议明确指定目标。

如果数据库已经存在超级管理员标记，则始终沿用其中绑定的用户 ID；修改或删除环境变量都**不会**重新分配超级管理员，也不会创建第二个。环境变量只是首次部署/旧数据库迁移的引导参数，不是长期修改权限的开关。

之后所有密码验证以 auth.db 中的 scrypt 加盐哈希为准；改密码后即使 .env 保留初始密码，也不能再用旧密码登录。两个 SQLite 文件都必须备份。永远不要删除 auth.db 来重置账号，否则现有任务归属将失去关联；忘记所有管理员密码时应通过受控恢复备份解决。

## 权限矩阵

| 操作 | 管理员 admin | 普通用户 member |
| --- | --- | --- |
| 登录、提交新解析任务 | 是 | 是 |
| 查看历史、详情及下载 MP4/TXT/MD/ZIP | 全部用户 | 仅自己 |
| 删除任务及任务关联的文件 | 全部用户 | 仅自己 |
| 创建用户、选择普通或管理员 | 是（不能通过创建用户获得超级管理员权限） | 否 |
| 查看所有用户、调整角色、停用账号 | 是 | 否 |
| 重置其他用户密码 | 是（受保护的超级管理员除外） | 否 |
| 修改自己的密码（需要当前密码） | 是 | 是 |
| 降级或停用最后一位管理员 | 禁止 | 无权限 |

普通用户即使知道其他任务 ID、下载路径或文件名，也无法通过历史 API、文件接口和 ZIP 下载访问他人资料。管理员历史列表可显示任务归属用户。禁用或角色调整后，该用户原来的网页登录会话立即失效。管理员不可以从管理页面禁用自己，重置自己的密码仍需在“我的账号”输入当前密码。

## 具体操作

登录后，右上角的“账号”用于自己修改密码，“用户管理”仅管理员可见。管理页面可创建用户、设置至少 8 个字符（允许 # 等特殊符号，不强制字符组合）的初始密码、选择普通用户或管理员、切换角色、停用/启用账号和重置其他用户的密码。修改自己的密码后要重新登录；管理员重置别人密码后，对方旧会话即时失效。

不提供公开注册，也不直接删除用户资料；停用比删除安全，原历史保持可追溯。

## 会话和安全设计

- 每个密码用 Werkzeug scrypt 加盐哈希，不存明文。
- Session Cookie 默认 Secure、HttpOnly、SameSite=Lax，最长 12 小时；每次请求校验当前账号状态与会话版本。
- 表单和网页登录 API 写操作均验证 CSRF；账户登录失败按账户和来源限流；更改角色、禁用或改密码都撤销旧会话。
- 初始配置 WEBUI_COOKIE_SECURE=true，不依赖 PUBLIC_BASE_URL 是否为空；NPM 在公网终止 TLS，容器内 HTTP 不应让浏览器退回不安全 Cookie。
- 为保留原有命令行 API 兼容性，显式 HTTP Basic 仍可用，但始终对当前 auth.db 验证、受登录限流及跨站请求限制。修改密码后旧的 Basic 凭据失效。
- 用户文件通过数据库任务归属验证，重复文件名不能绕过权限；如文件仍被其他任务引用，删除一个任务不应误删共享文件。
- 不要提交 .env、auth.db、history.db、Cookie、会话或下载媒体到 Git。

## 重要边界

本次是 WechatVideoDL 页面、API、历史和本地文件的权限隔离。现有元宝分析仍共用服务端 Yuanbao 凭据与会话环境，**并未变成每个用户拥有独立 Yuanbao 账号或外部 AI 会话**。因此不能声称全链路具备第三方平台的强多租户隔离。用户的任务处理仍共享一个本机解析队列与 SenseVoice 工作进程。

生产部署必须先备份私有数据、执行 deploy.sh --dry-run，部署后以旧账号登录确认管理员和旧历史保留，检查普通用户之间的文件越权，以及公网 HTTPS、NPM 反代、SenseVoice 和 Browserless。


## 通用的唯一超级管理员机制

- 超级管理员的名称由部署者决定，不使用硬编码名称。干净安装自动将初始管理员 (WEBUI_USERNAME) 设为唯一超级管理员。旧版多管理员账号库可通过私有 SUPERADMIN_BOOTSTRAP_USERNAME 完成一次性选择。
- 数据库存储唯一 is_superadmin=1 标记，并以原用户 ID 绑定身份；只有旧版数据库**还没有任何超级管理员**时才进行引导。后续更改配置、增设管理员或新增同名用户都不能转移此身份。
- 超级管理员保留 role=admin 与现有管理接口兼容。其他管理员不能重置其密码、更改角色、启用/停用或删除此身份；约束落实在管理路由、账号存储方法以及 SQLite 唯一索引与防篡改触发器中。
- 超级管理员可以在“我的账号”提供当前密码后自行改密；旧会话失效。本人不能从管理员快捷重置入口绕过旧密码验证。
- 普通管理员仍可管理其他用户，不能手动设置第二个超级管理员。没有公开的超级管理员身份转移 API；如果将来确需移交，应该设计额外的安全流程，而不是修改环境变量。
- 使用者可以把自己想保护的账号名放在部署机器私有 .env，但示例文件、源码、测试和上游 PR 不包含任何特定部署者账号。
- 此保护属于 WebUI/应用/SQLite 正常操作的权限边界。拥有宿主机系统管理员权限并能够直接修改应用代码或数据库文件的人，仍位于此权限边界之外。
